# 作品コンテンツ編集ガイド

このガイドは、作品を追加・更新する人向けの手順書です。初めて追加するときは「作品追加は雛形生成から始める」と「公開前に品質ゲートを通す」を順に読んでください。各フィールドの意味は、編集に迷ったときだけ参照すれば十分です。

このガイドで判断できない事実は推測で埋めず、変更を止めてサイト所有者へ確認してください。

## 作品追加は雛形生成から始める

作品のURLに使うslugを決め、プロジェクトルートで次のコマンドを実行します。

```bash
npm run content:new -- my-new-work
```

slugに使える文字は英小文字、数字、ハイフンです。コマンドは次の2か所を作成します。

- `src/content/works/my-new-work.ts`
- `public/images/works/my-new-work/`

同名のファイルか画像ディレクトリがある場合は上書きしません。生成直後の作品ファイルには空欄があり、`npm run check`は失敗します。これは未確認の情報を公開しないための意図した動作です。次節を見ながら必須項目を埋めてください。

画像を使わない作品では、空の画像ディレクトリを削除して構いません。Gitは空のディレクトリを記録しないため、画像を置くまではコミットにも含まれません。

## 一覧と詳細ページに必要な情報を埋める

作品ファイルは末尾の`satisfies Work`によって型を検査します。フィールド名は変更せず、値だけを編集してください。

| フィールド         | 入力内容                                                          |
| ------------------ | ----------------------------------------------------------------- |
| `id`               | 原則としてslugと同じ値。既存作品と重複させない                    |
| `slug`             | URLの一部。ファイル名と同じ英小文字・数字・ハイフンの文字列       |
| `title`            | 公開する作品名                                                    |
| `summary`          | 一覧用の要約。改行なし、80文字以内                                |
| `introduction`     | 詳細ページの紹介文。段落ごとに配列へ分ける                        |
| `category`         | `vrchat-world`、`avatar-3d`、`game`、`vket`のいずれか             |
| `status`           | 下表の公開状態から選ぶ                                            |
| `role`             | 下表の制作上の役割から選ぶ                                        |
| `period`           | 制作年を`YYYY`で記入。不明なら`null`                              |
| `firstPublishedAt` | 初回公開日を`YYYY-MM-DD`で記入。不明なら`null`                    |
| `featuredOrder`    | ホームの代表作に出す場合は1以上の重複しない整数。それ以外は`null` |
| `verifiedAt`       | 内容を最後に確認した日付を`YYYY-MM-DD`で記入                      |

ゲーム作品には`gameDetails`が必要です。`genre`と、分かる場合は`developmentTool`を記入します。Vket作品には`vketExhibition`が必要です。それ以外のカテゴリには、これらのカテゴリ固有フィールドを追加しません。

### 公開状態は確認できた事実に合わせる

| 値                           | 用途                                   |
| ---------------------------- | -------------------------------------- |
| `published`                  | 現在公開中と確認できた作品             |
| `recent-evidence`            | 最近の公開痕跡を確認できた作品         |
| `recent-public-record`       | 最近の公開記録を確認できた作品         |
| `confirmed-record`           | 記録として存在を確認できた作品         |
| `unverified`                 | 現在の状態を確認できない作品           |
| `stopped-with-public-record` | 開発停止を確認でき、公開記録が残る作品 |
| `archived`                   | 公開終了またはアーカイブ済みの作品     |

### 制作上の役割は断定できる範囲で選ぶ

| 値                     | 用途               |
| ---------------------- | ------------------ |
| `self-produced`        | 自主制作           |
| `model-creator`        | モデル制作者       |
| `collaborator`         | 委託・共同制作     |
| `programming-support`  | プログラミング支援 |
| `exhibitor`            | 出展者             |
| `pending-confirmation` | 役割を確認中       |

## 画像は作品専用ディレクトリへ置く

画像は`public/images/works/<slug>/`へWebP形式で置き、作品ファイルから`/images/works/<slug>/ファイル名.webp`として参照します。

- `heroMedia`は一覧と詳細ページの主画像です。画像がなければ`null`にします。
- `media`は詳細ページのギャラリーです。主画像と同じURLを重複させません。
- `alt`には、画像を見なくても内容が分かる短い説明を書きます。
- `caption`は補足が必要な画像だけに付けます。
- `credit`は権利者や撮影者の表示が必要な場合に記入し、不要なら`null`にします。

出所や権利を確認できない画像は追加しません。

## 公式リンクと出典を分けて記録する

`links`は訪問者が作品を入手・閲覧する行き先です。通常は`primary`タグを持つリンクを1件だけ置きます。補助的な行き先には`action`、関連記事には`related`を使います。公開終了した作品だけは、リンクを空にできます。

`sources`は掲載内容を確認した根拠です。表示用リンクと同じURLでも、役割が異なるため省略しません。各出典には次を記入します。

- `label`: 出典名
- `url`: 確認できる公開URL
- `kind`: `first-party-public`、`third-party-public`、`person-confirmed`のいずれか
- `verifiedAt`: 最後に確認した日付
- `role`: Vketカタログやイベント投稿など、用途を区別するときだけ指定

確認できない項目は`factsPending`へ記録します。`field`には`current-status`や`first-published-at`など`src/content/types.ts`で許可された値を使い、`note`に未確認の内容を書きます。

## ホーム掲載は作品データの完成後に設定する

ホームの代表作は、作品の`featuredOrder`で決まります。数値は1から始め、ほかの作品と重複させません。

「つくっているもの」の活動カードは`src/content/home.ts`の`activities`で管理します。

- 作品カードは`kind: 'works'`とし、活動領域の`areaId`、カテゴリ、表示する`workSlugs`を指定します。
- 「N作品を見る」の件数とリンク先は自動生成されるため、手書きしません。
- 外部カードは`kind: 'external'`とし、`areaId`、案内文、画像を指定します。URLは対応する活動領域から取得されます。

ホーム下部の公式リンクは`primaryLinks`へ`linkId`と短い表示名を追加します。存在しない活動領域、作品、公式リンクを指定すると、コンテンツ検証が失敗します。

## 公開前に品質ゲートを通す

編集中はコンテンツテストだけを実行すると、問題を早く確認できます。

```bash
npm run test:run -- src/content/content.test.ts
```

編集が終わったら、リポジトリ全体の品質ゲートを実行します。

```bash
npm run check
```

エラーには`works[0].summary`や`home.activities[1].workSlugs[0]`のような場所が表示されます。該当する作品またはホーム設定を直し、すべて成功するまで公開用コミットへ含めません。
